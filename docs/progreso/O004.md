# O004 — Python embebido en los instaladores

**LISTA PARA REVISIÓN**

La app ya se puede instalar en una máquina sin Python: el .deb y el setup de Windows
llevan su propio intérprete con IfcOpenShell y numpy en `recursos/python/`. La prueba
de Linux arranca el binario extraído del .deb con `PATH` sin Python y comprueba
`nucleo.ping`, proyecto nuevo, muro, guardado, reapertura y teselado. La de Windows
instala el setup en silencio y ejecuta el mismo intercambio JSON-RPC contra el
`python.exe` embebido.

## Qué se hizo

### 1. `herramientas/preparar_python.sh <linux|windows>`

- **Windows:** baja el embeddable oficial `python-3.12.9-embed-amd64.zip` (SHA256
  `615861fb…5865`), descomprime, descomenta `import site` en `python312._pth` y agrega
  `Lib\site-packages` y `nucleo`.
- **Linux:** baja python-build-standalone `cpython-3.12.15+20261021`, variante
  `install_only_stripped` (SHA256 `6d752113…e772`), y hace `pip install --target` de los
  paquetes en `lib/python3.12/site-packages`.
- Paquetes fijados: `ifcopenshell==0.9.0.post1`, `numpy==2.5.4`, `shapely==2.2.0`,
  `isodate==0.7.2`, `python-dateutil==3.0.0`, `lark==1.3.1`, `pyparsing==3.3.3`,
  `typing-extensions==4.16.0` y `six==1.17.0` (cadena real de importación comprobada).
- Copia `nucleo/openrvt_nucleo` a `recursos/python/nucleo/` y deja una ruta relativa en
  `openrvt-nucleo.pth` (Linux); en Windows la ruta va en `python312._pth`.
- Recorta `__pycache__`, `tests/`, `idlelib`, `tkinter`, `ensurepip`, `pip`, `include`,
  `share`, Tcl/Tk y los conectores de IfcOpenShell que el núcleo no usa (Collada, IGES,
  OBJ, glTF, SVG, TTL) y los núcleos de geometría alternativos. También quita el
  `libpython*.so` de Linux, que el ejecutable de python-build-standalone no necesita.
- Imprime el peso suelto y comprimido y, en Linux, comprueba los imports.

### 2. Empaquetado Tauri

- `bundle.resources` incluye `recursos/python/` como lista (la forma de mapa/glob de
  Tauri aplana los archivos y rompía `bin/` y `lib/`).
- En el .deb los recursos quedan en **`/usr/lib/OPEN-RVT/recursos/python/`**, no junto a
  `/usr/bin/open-rvt`. Por eso `nucleo.rs` ahora resuelve la carpeta con
  `app.path().resource_dir()` y la usa para el intérprete y para `PYTHONPATH`.
- Se mantiene el orden: `OPENRVT_PYTHON` → recursos de Tauri → `recursos/python` junto
  al ejecutable → `python3`/`python`.
- En Windows el `Command` usa `CREATE_NO_WINDOW` (el intérprete sigue siendo `python.exe`
  para conservar stdin/stdout del JSON-RPC).
- Versión **0.2.0** en `package.json`, `Cargo.toml`, `Cargo.lock`, `package-lock.json` y
  `tauri.conf.json`.

### 3. Pruebas

Prueba de extremo a extremo de la app empaquetada, sin Python del sistema (un `PATH`
con `python`, `python3` y `python3.12` falsos que fallan):

```
$ OPENRVT_E2E_BINARIO=/tmp/.../usr/bin/open-rvt \
  xvfb-run -a node --test e2e/o004.test.js
✔ O004: .deb con Python embebido responde ping, crea muro y guarda (1.4 s)
ℹ tests 1   pass 1   fail 0
```

El .deb se extrajo con `dpkg-deb -x` y se ejecutó el binario desde esa extracción. El E2E
comprueba `nucleo.ping` (`disponible: true`, IfcOpenShell `0.9.0.post1`), `proyecto.nuevo`
(IFC4), `muros.crear` (un `IfcWall`), `proyecto.guardar` y que el IFC contiene exactamente
un `IFCWALL(`. Captura: [`o004-linux-embebido.png`](../capturas/o004-linux-embebido.png).

Intercambio JSON-RPC directo contra el intérprete del .deb extraído:

```
$ env -u OPENRVT_PYTHON PATH=/usr/bin:/bin \
  python3 herramientas/probar_python_embebido.py \
  /tmp/.../recursos/python/bin/python3.12 /tmp/prueba-linux.ifc
OK: ping, proyecto nuevo, muro, guardado, reapertura y teselado (5262 bytes)
```

Windows: setup instalado en silencio con `/S /D=C:\...\openrvt-o004-final`.

## Pesos

| Plataforma | Python suelto | Python comprimido | Instalador |
| --- | ---: | ---: | ---: |
| Linux | 221 MiB | 65,2 MiB | `OPEN-RVT_0.2.0_amd64.deb`: 77 171 910 B (73,6 MiB / 77,2 MB) |
| Windows | 163 MiB | 54,0 MiB | `OPEN-RVT_0.2.0_x64-setup.exe`: 41 531 376 B (39,6 MiB / 41,5 MB) |

Los dos instaladores quedan por debajo de la meta de 80 MB comprimidos (medida decimal).

## Desviaciones

1. **Variante de python-build-standalone.** Se usa `install_only_stripped` en vez de
   `install_only`: la variante normal trae símbolos de depuración (65 MB de descarga
   frente a 33 MB) y `strip` del sistema corrompe los símbolos versionados del ejecutable
   (`undefined symbol: , version`). La variante recortada es el mismo Python 3.12.15.
2. **Versión de Windows.** python.org solo publica el embeddable de Windows hasta 3.12.9;
   Linux usa 3.12.15 de python-build-standalone. Ambas son 3.12 y las ruedas son cp312.
3. **Recorte adicional de IfcOpenShell.** Para cumplir el límite de peso se quitaron
   conectores de formatos que el núcleo no importa ni usa y los núcleos de geometría
   alternativos (el núcleo tesela con OpenCASCADE). Se conservan los esquemas IFC2X3,
   IFC4 e IFC4X3 y los conectores de geometría de esos esquemas. Se comprobó abrir y
   teselar `AC20-FZK-Haus.ifc` (IFC4) y `IFC2X3-Building-Architecture.ifc` (IFC2X3).
4. **`libpython` fuera en Linux.** El ejecutable de python-build-standalone es autónomo;
   se quitó `libpython3.12.so` (30 MB) y se verificaron imports, teselado, guardado y
   reapertura con ese árbol.
5. **Prueba de Windows.** No se ejecutó la GUI con WebDriver en Windows: se instaló el
   setup en silencio y se probó el intérprete embebido y el protocolo JSON-RPC completo,
   que es lo que pide la spec para esa plataforma. El arranque sin consola se implementó
   con `CREATE_NO_WINDOW` (el flag no es observable desde WSL).
